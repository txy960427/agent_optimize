# 数据与接口能力草案

状态：v0.9 · 2026-11-25。当前已接入实际JSON离线导出，详见[REAL-DATA-WORKSPACE.md](REAL-DATA-WORKSPACE.md)。本轮同步全书目录、教学数据边界、对象浮窗和入口可用性；数据接入职责、阅读/实操恢复及表单草稿语义继续沿用。这里定义应用需要的能力和自身数据结构，**不是内部Langfuse已存在的接口或已确认字段**。接入前按部署版本核对。

## 1. 数据流与职责

当前由本地只读服务读取data目录中的实际Langfuse导出，浏览器请求分页摘要和单条Trace，人工调查保存在本机。原始记录不改写，来源指纹、人工映射与字段引用分开保存。LLM入口禁用，不再提供预设意见。以下身份认证、实时Langfuse与协作存储约定用于后续接入，当前没有连接这些服务。

```text
浏览器：课程、查看器、人工判断、单次辅助入口
  → 本站服务：用户会话、项目访问、查询适配、证据引用、调查记录
      → 内部 Langfuse：会话 / Trace / Observation / 输入输出等只读查询
      → 已配置 LLM：用户主动触发的一次辅助请求
      → 应用存储：SOP 版本、人工判断、笔记、候选与验证计划
```

Langfuse API 凭据保留在服务端。用户授权范围随查询和证据读取执行；不把长期密钥放进前端或让浏览器直接绕过本站访问控制。实际部署已有统一认证时优先接入，不另造重复登录流程。

本站输出人工标记、候选对象和归因，不修改 Langfuse 原始记录。首期只读接入；写回 score/tag 等属于后续明确需求。

## 2. 必需能力与 UI 状态

| 能力 | 输入 | 输出至少包括 | 需明确的限制 |
| --- | --- | --- | --- |
| Session 精确查找 | 项目、Session ID | 会话关联 Trace、时间、分页 | Session 的存储/查询方式依版本确定 |
| 关键词检索 | 项目、词、时间、范围 | 命中 Trace / Observation、字段与片段 | 可搜哪些字段、是否全文、大小写/分词、扫描范围 |
| Trace 详情 | Trace ID、项目 | 关联会话、请求/回复摘要、关联记录 | 顶层 input/output 可空，摘要不代表完整上下文 |
| Observation 读取 | Trace 或记录 ID | 类型、父子关联、时间、状态、实际 input/output | 分页、嵌套、大小限制、截断、权限和记录类型 |
| 证据原文 | 记录 ID、字段路径 | 内容、完整性信息、来源与版本 | 不可用与空内容区分；附件是否可读 |
| 调查保存/恢复 | 调查 ID、版本及事件 | 保存版本、当前阶段、未决项 | 并发版本冲突不得静默覆盖 |
| 单次 LLM 辅助定位 | 方法、Trace/循环范围、预期、记录引用及映射版本 | 候选循环/环节、偏差说明、依据、回查建议、缺口 | 不越过已选范围；建议与人工确认分开 |
| 单次 LLM 辅助判断 | 当前节点、循环/环节、引用、预期 | 建议答案、引用、缺口、请求状态 | 模型内容上限、一次调用、失败/取消状态 |

如果部署 API 不支持所需全文检索，需要明确采用获授权的服务端有界扫描或检索索引。页面应展示覆盖范围；不能只在当前页过滤后声称全量查询完成。

## 3. 应用数据实体

这些是概念字段，后续接口设计可以调整命名；实体关系先保持稳定。

| 实体 | 关键内容 | 关系与约束 |
| --- | --- | --- |
| OptimizationObject | id、parentId、分组/对象类型、名称、定义、作用、学习目标、实操目标 | parentId表达从属；节点仅名称，浮窗仅定义/作用及可用入口；当前仅模型入口可用，其他禁用，不能按course字段推断所有入口已开放 |
| ObjectRelation | id、sourceId、targetId、关系类型、方向、标签 | 表达信息/控制/反馈，不能用parentId冒充执行关系；图中分开呈现 |
| ViewState | 用户/项目/调查范围、选中对象/视口、课程/锚点/滚动、阶段/循环/环节/原始记录、各方法输入、当前证据视图与草稿 | 只保存位置与草稿，不等于已提交判断；跨页面/视图恢复需核对版本和权限 |
| Investigation | id、用户/项目、现象、预期、阶段、版本、SOP版本、时间 | 一次调查可引用主要 Trace 及对照 Trace |
| SourceRecord | 平台、项目、session/trace/observation ID、父ID、类型、时间、读取时间、内容版本 | 保留原始数据和原始 ID，不把人工笔记混入 |
| EvidenceRef | 原记录引用、字段路径、片段范围、原文哈希/快照版本、可读性与完整性 | 引用能回查到当时的来源；原始记录变更时可识别 |
| AnalysisStep | id、traceId、kind（loop/request/delivery/unclassified）、loopIndex（如适用）、映射版本、上下游依赖 | 主定位步骤为一次循环；①/⑥为单独边界，待分类记录保留，不伪造循环 |
| PhaseMapping | stepId、phaseId（①–⑥）、Observation引用、关系、可见性/完整性状态 | loop内部通常映射②–⑤，request对应①，delivery对应⑥；一环节可有多记录，跨循环容器独立保留 |
| ContextSegment | 实际模型调用、消息序号/字段路径、来源标签、原文范围、标签创建者 | 只作阅读分类，保持角色、顺序和原文；允许未知 |
| StepCheck | stepId、可选phaseId、方法、预期版本、实际引用、用户判断、原因、角色标记 | 可先选循环再细到环节；①/⑥可直接检查；关键与受影响位置可多选 |
| Decision | 路径/节点ID、答案、依据、证据引用、用户、时间、依赖版本 | 三标准分别记录；证据不足不是 false |
| Assistance | taskType（locate/judge）、方法/节点、Trace与步骤范围、预期/映射/证据版本、模型、请求状态、输出、用户后续处理 | 定位与判断分开；人工确认不替代原建议，不自动修改映射或已提交判断 |
| LocationSuggestion | 辅助请求ID、stepId、可选phaseId、偏差说明、记录引用、回查建议、缺口、用户处理状态 | LLM输出或规则线索为建议；加入待核对不等于确认关键位置 |
| PendingTask | 缺失内容、原因、关联判断、来源要求、状态、补充引用 | 补充材料有独立来源，完成后提醒复核相关节点 |
| Candidate | 对象ID、路径/步骤、支持与反向证据、未决项、优先级理由 | 可以多个，没有经校准的概率字段 |
| Verification | 待验证假设、计划、条件、对照、结果和回归检查 | 计划与实际结果区分，保存结果不代表系统已执行 |

对象关系数据不包含布局说明或受众文案。根级概览可对应总纲继续阅读，子对象学习目标必须落到更深入正文；若目标只会跳回同一地图，应在内容路由映射中修正。

三标准共享当前调用的EvidenceRef，用户可追加片段；每项答案独立。“满足”的备注可空，“不满足/证据不足”保留具体偏差或缺口。LLM采纳先更新草稿，显式提交才写入有效Decision。

### Trace 到循环/环节的映射约束

原始结构仍是 Session/Trace/Observation；Loop与六环节是本站按照实际埋点建立的教学映射，不是Langfuse平台固有字段。

- ①/⑥属于外层；主定位步骤为一次循环，②–⑤按实际发生映射，不能默认每步六环节。
- 模型调用前的②归属于该调用所在循环；上一轮⑤传来的信息是它的上游引用，不把同一条记录复制成两次执行。
- 环节可以包含多条记录；容器或共享准备可跨循环，用关系引用表达，不强行归一个循环。
- 并行和重试保留分支、依赖与尝试；循环编号只是可读顺序，不证明全局因果。
- 无法识别循环或环节时允许未分类，用户确认后保存映射版本。没有映射不能伪造LLM候选ID。

## 4. 查询与证据完整性

- 统一标识项目和数据来源，避免相同 ID 跨项目误配。界面显示时间所用时区。
- 首次读取记录读取时间与内容版本；后续刷新提示哪些数据新增或变化，不静默改变已提交判断依赖的证据。
- 数据过大时可先加载目录和摘要，但必须标记正文尚未全读。查齐上下文后才可以谈完整性。
- 原始 input 是数组、JSON、文本或多模态结构时保留结构，不拼接成一段无法回溯的摘要。
- 对无法打开的引用、脱敏、截断、采样或缺埋点分开标识。不以 token 数/耗时/非空字段证明语义材料齐全。
- 原记录不可再访问时说明权限/删除/网络等原因，历史笔记仍可存在，但证据状态变为不可回查。
- 观察记录中的模型输出若包含接口显式提供的推理内容，可按实际返回展示；不推断未记录的内部推理。

## 5. 决策状态与失效规则

主阶段为 `case → steps → locate → context → decide → findings`；另保留 `waiting_for_evidence`、`needs_review`、`saved` 等工作状态。名称是建议。

| 变更 | 影响 |
| --- | --- |
| 更换主 Trace 或增加对照轮次 | 重新核对范围和受影响的步骤/判断 |
| 修改循环边界、环节或记录关联 | 保留旧映射版本，相关定位建议、标记与下游决策待复核 |
| 更新业务预期 | 相关符合性检查、三标准判断和候选待复核 |
| 更新输入/补充证据 | 依赖该证据的判断和 LLM 意见标为旧版本 |
| 修改上游答案 | 保留旧路径，当前路径依赖部分待复核 |
| 升级 SOP | 旧调查绑定旧版；用户明确迁移时核对节点差异 |

可以用 XState 描述事件与合法转换，但机器状态不等于数据持久化。服务端仍需保存调查、事件/版本、证据引用和访问权限。

### 视图与业务变更分开

- 切换消息/JSON、定位方法、展开图或返回课程属于视图变化，不重新运行诊断、不清空答案、不隐式提交。
- 阅读页记录来自哪次调查，返回复用该调查；纯学习入口只携带主题，不创建虚假的已选Trace或绕过证据准备。进行中的辅助请求绑定同一请求ID，返回只恢复状态，不重复调用。
- 恢复时先核对源记录/映射/权限；位置可恢复但证据已变，则显示待复核，不能无提示沿用旧判断。
- 草稿保存、判断提交、辅助请求各自有状态；保存失败保留当前内存输入并允许重试，不能显示“已保存”。离开未保存内容时给出明确处理方式。
- 选择Trace的预览态、主要项单选和进入调查是不同状态，但不要求重复点击“设为主要Trace”。查询结果切页/失败仍保留参数与有效选择。
- SOP/映射/模型版本等保留在记录中，界面按需展开；查询覆盖、截断、权限等会影响当前判断的信息即时显示。

## 6. 单次辅助请求的契约

- 输入共同部分：用途、SOP条款、用户已确认的预期、选择的Trace/循环/环节范围、证据引用及可见原文、内容缺口。业务预期未确认时明确标记，不能用模型猜测替代。
- 定位输入另含当前方法、映射版本和搜索词/状态（如有）；一次请求覆盖明确范围，不按每个循环自动发起多次调用。
- 判断输入另含当前节点问题和目标模型调用；当前循环中实际存在多个相关调用时由用户选定，不任意使用最后一次。
- 记录：模型/配置版本、预期/映射/证据版本、请求时间、状态、可获得的用量信息。无用量数据就不展示虚构费用。
- 定位输出：候选stepId/phaseId、实际记录引用、偏差说明、支持/反向依据、建议回查方向、缺失信息。只知道已选范围内的偏差时，不声称整个Trace或Session的第一处根因。
- 判断输出：建议答案（含无法判断）、支持和反向证据引用、未决事项。
- 服务端校验候选ID属于请求范围及映射版本，引用能定位真实片段；验证失败的输出不进入已确认候选。
- 不静默截断大输入；先提示范围与上限，由用户缩小或分开判断。
- 超时或取消后，服务端按请求 ID 去重；用户重试前明确上次状态，避免重复请求被误当一次。
- UI 不自动勾选用户答案；定位可加入待核对，确认关键位置与决策答案都需用户提交；推理与生成错误都有独立反馈。

## 7. 接入前核对清单

以下是后续接入所需资料，不阻塞当前产品设计，也不要求现在提供密钥。

1. 实际部署版本、实例入口、项目与相应版本 schema；如实例提供 OpenAPI 文档则以它为准。
2. 一条可读取、具有代表性的 Session 与完整关联记录；最好覆盖多轮、工具调用、压缩或重试。
3. 模型实际输入输出字段及其完整性约定；埋点名称、父子关系、循环边界与②–⑤映射。
4. 关键词需要覆盖的字段、时间范围、数据量及 API 的过滤/分页能力。
5. 本站既有认证、数据留存和 LLM 调用服务配置。

官方能力参考：[Langfuse API & Data Platform](https://langfuse.com/docs/api-and-data-platform/overview)。当前官网可以证明平台有开放数据能力，不能证明内部部署支持最新版本的全部端点和过滤条件。

平台层级参考：[Langfuse Core Concepts](https://langfuse.com/docs/observability/data-model)。Trace对应应用定义的请求或操作，不能保证一次Trace恰好就是一轮用户对话。

## v0.9 已实现的本地导出适配

详见[REAL-DATA-WORKSPACE.md](REAL-DATA-WORKSPACE.md)。当前GET接口为manifest、分页traces、traces/:id、traces/:id/raw、cases；写方法拒绝。源数据不进入public或静态bundle。归一化摘要与原始输入输出分开，Observation保持导出形式，按ID保存全部来源并检测重复冲突。

映射以model节点和父子关系生成草稿，辅助GENERATION不计作主循环。每条记录出现在接收、交付、容器、循环环节或待分类中，检查记录总数守恒；⑤没有独立埋点时留空。人工修正保存在Investigation，修改映射/模型目标会保留历史并使下游待复核。

上下文角色与阅读来源分组独立：role=tool可能承载工具定义，不能一律归为执行反馈。分组只辅助阅读，保留原消息序号与结构；零计数不证明来源缺失。EvidenceRef实际记录字段/消息路径，原文折叠不等于数据截断。

本机调查key为agent-tuning-real-export-v1，与旧模拟记录隔离。保存字段含Trace ID、源指纹、映射修正、选定模型、人工判据、引用与验证文本，不保存整包原始数据。源指纹变化需复核。空Session不用于关联其他空Session记录。参考分析作为caseReferences保留来源，不注入用户答案。
