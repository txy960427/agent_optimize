## 核心定位

本指南针对医疗设备智能体，提供覆盖调优全链路的方向、技术方法与内部技术案例指导，统一团队方法论，使调优有章可循、有人负责、有案例可查，并能持续沉淀经验和数据资产。名称保留《智能体调优技术指南》，具体对象明确为医疗设备智能体。

前言强调对归因、方法、验证与资产四个不统一建立规范。目录、案例和交互应服务“怎样选择方法、依据是什么、责任如何衔接、如何验证和复用”。稳定安全的设备任务交付是调优目标，三层职责是具体框架；二者不能取代指南本身的定位。

材料中的医疗化约束落在医疗设备智能体的任务与工程场景，需核对设备业务、安全边界、端侧资源、可追溯证据和回归要求。不能把范围写成泛医疗行业。具体职责与方法仍须以实际材料和案例为依据。

## 四项目标

| 目标 | 对内容组织的要求 |
| --- | --- |
| 有章可循 | 方法有明确准入条件、适用边界和选择依据 |
| 有人负责 | 每类问题有明确的责任团队与流转路径；未知团队映射不编造，技术架构层级不能代替责任分工 |
| 有案例可查 | 方法关联内部案例，保留现象、轨迹、判断与验证过程 |
| 有资产可沉淀 | 沉淀轨迹、数据集、判据、失败模式和回归样本，支持受控复用 |

前言指出归因、方法、验证、资产四个方面缺少统一规范；本指南以统一框架回应。首页不能只表达原理入门和Trace排查。

## 方法与范围

- 归因核对顺序：先环境、再Harness、后模型；证据不足可以保留未决项，不能机械自动定因。
- Harness重点包括提示词、上下文与记忆、知识库、工具调用、Skill、多Agent编排、安全护栏和决策方式。
- 模型训练需以严格归因为前提，包括SFT、Agentic RL、蒸馏及端侧约束下的模型体系、端云协同；当前页面只有基础内容，不能冒充已有完整课程。
- 自进化为受控经验复用；候选生成不等于自动上线。
- 数据飞轮由数据构造、模拟仿真、测评及回归等环节支撑。固定任务集、口径和版本使验证可比较。
- 运行环境具体工程优化不在范围。第4章保留原章名，但明确只界定归因边界和责任衔接。

## 三种使用路径

| 路径 | 使用情境 | 阅读与工作顺序 |
| --- | --- | --- |
| 问题驱动（常用） | 已有具体问题与追踪记录或Badcase | 总纲归因 → Harness/模型专项 → 自检与验证 → 修复样本进入回归 |
| 系统建设 | 新建或重构智能体 | 建立目标和责任 → 设计Harness主线 → 建立数据集与回归 → 按条件启动模型训练 |
| 方案评审 | 调优方案或发布申请 | 核对准入条件、验证证据、版本责任和回退；详细检查表随材料补齐 |

角色包括BU智能体研发、AIC智能体团队、AIC大模型团队、框架、应用工程、测试、产品及架构评审者。不根据截图缺失处猜测各角色的确切必读章节。

## 对当前原型的约束

1. 两版首页同定位、同目标主标题；书名由全局品牌与首页1的书封承担，首页不重复书名大标题。
2. 首页先说明医疗设备智能体的方向、技术方法与案例指导。首页2沿用左右阅读页，播放“发现问题→定位对象→专项方法与案例→验证→沉淀、持续测评与更新”的完整SOP，不再用归因片段代表整本指南。阅读、实操与章节入口保留，三种完整使用路径留在前言。
3. Langfuse是问题驱动路径的证据来源和工作入口；当前已读取实际JSON离线导出，范围不等于内网实时全量查询。
4. 原理演示作为前言补充，前言先交代背景、目标、范围和路径。
5. 统一验证、责任流转与资产复用是指南要求；本轮不据此扩建尚未授权的完整评审或资产管理后台。
6. 章节状态必须真实：缺少正文、检查清单、真实案例的部分说明待补充，不提供空白链接。
