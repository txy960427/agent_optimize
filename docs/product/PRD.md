## 1. 产品要解决的问题

本指南为医疗设备智能体提供调优方向、技术方法与内部案例指导。前言指出团队在归因、方法、验证、资产四个方面缺少统一规范，需要覆盖调优全链路的方法论，使调优有章可循、有人负责、有案例可查，并积累可复用资产。稳定、安全地完成设备相关任务是要改善的结果，不能代替指南的服务定位。

《智能体调优技术指南》覆盖完整工程方法，目标是有章可循、有人负责、有案例可查、有资产可沉淀。网站承担阅读、交互讲解、案例实操和方法复用；问题驱动、系统建设、方案评审是并列的使用情境。Langfuse工作台用于问题驱动路径中的证据检查，不代表全部指南。

三层职责由运行环境、Harness、模型共同组成。归因先环境、再Harness、后模型；严格归因后选择专项改进，以固定任务集、口径和版本验证，再把已验证样本与判据纳入回归和受控迭代。

具体环境工程优化不在本指南范围，第4章仅界定归因边界。医疗设备智能体的业务约束、安全边界、证据可追溯、端侧资源和验证要求贯穿方法。候选生成不等于自动上线。

4. 查询、查看数据、拆步骤、核对和决策在本站完成。Langfuse 原链接作为可选的来源追溯入口。
5. 用户主导判断；可在当前判断点主动调用一次 LLM 辅助，查看后再决定是否采纳。
6. 支持补材料、暂存、回退和修改。证据不足是有效工作状态。
7. 对象导览直接可查看 Harness 下的记忆、Prompt、Skill、工具、架构设计。所有对象均可悬浮或点击查看定义与作用；说明采用浮窗，不占永久右栏。浮窗只保留一个小入口，目前仅“模型”的“进入模型优化”可用，跳至已有模型课程；其余对象显示禁用的“对应内容待开放”。不在导览浮窗加入证据、检查项或诊断建议。
8. 受众说明、布局尺寸、设计提醒等不进入页面布局文案；真实影响用户任务的提示，如缺失记录、权限、截断和未保存状态，应保留。
9. 信息结构决定组件：关系用图、对照用表、互斥视图用标签、任务顺序用阶段导航、判断用表单。开源库是实现手段，不用统一卡片或复杂控件套所有内容。

## 5. 学习端需求

### L0 指南首页与前言

- 固定导航同时提供首页1（书册视觉）与首页2（保留左右阅读页、完整SOP情境演示）。主标题为“医疗设备智能体的调优方法与实践”，不重复全局书名。
- 首页只提供阅读与实际排查两个直接入口。三种使用路径保留在前言，是指南阅读建议，不是三个已实现的工作模块。Agent内部循环、输入核对和详细方法在对应章节展开。
- 四项目标带简释，同时呈现。有人负责指责任团队与流转路径，不能用三个技术层代替。首页2用设备号重复追问情境串起总纲归因、对象专项技术与实践案例、验证、案例/回归沉淀、持续测评与指南更新。情境明确标记，不挂伪造Trace，不自动形成根因或声称验证成功。
- 默认按五阶段播放，常驻时间线显示整体顺序，右页随阶段切换并逐项展开；支持暂停、手动查看、下一阶段和重播。手动操作停止自动推进，减少动态效果时只允许手动。播放保持面板高度稳定；离屏和页面隐藏时停止计时。
- 方法和案例尚未补齐的章节明确待补充，不假设已具有真实评审、资产管理、数据集入库或持续测评后台。首页演示描述指南推荐的工作路径，真实工作台继续读取实际导出。
- 前言先覆盖背景、目标、适用范围、使用路径与协作维护，原架构教学作为补充。

- 首页展示第0—6章及内容状态；前言、总纲可阅读，模型现有整理稿标为基础内容，缺材料章节标为待补充且没有空白跳转。
- 主阅读入口从前言开始，目录可以直达总纲或模型；已有线索者可直接进入排查。
- 深色架构科普位于前言，用三个教学情境解释信息齐全时调用工具、缺少设备号时追问、工具超时时保留反馈。可播放、暂停、逐步、重置和查看组件。
- 教学情境为确定性的示例，不调用模型或Langfuse、不产生排查结果；未来真实排查仍遵循真实接口和人工SOP规则。
- 不把尚未实现的章节、实际训练结果或未知部署界面冒充已提供内容。

### L1 第1章导览与对象地图

- 导览解释“为什么先定位对象再优化”，介绍培训内容，并分流到继续学习或真实实操。
- 开篇短讲解后直接展示地图，地图承担主要篇幅；三条经验放在右侧紧凑栏，窄屏放下方。“开始阅读总纲 / 直接开始实操”统一放在地图之后，不在上方重复。
- 对象地图采用有语义的固定布局：模型与 Harness 为核心，环境提供运行条件，跨对象能力提供支撑。避免把对象随意连接成装饰性网络。
- 地图默认必须由交互图组件呈现，候选技术栈下使用React Flow分组节点和关系边。分组表示从属，箭头/标签表示信息与控制关系；文本树只作等价辅助，不是主地图。
- 模型、Harness、环境和支撑分组有明确色彩差异；协作动画默认连续播放，可暂停/继续；信号沿实际关系边移动，动画不改变用户选中对象，不自动答题或写入判断。减少动态效果模式默认暂停。
- 默认粒度到具体对象，Harness 下的记忆、Prompt、Skill、工具、架构设计直接可见、可点，不要求先点 Harness 才发现它们。模型下展示选型与替换、训练与能力提升、量化压缩；运行环境与安全监测按原图展示其下一层对象。更细的训练方法放入章节，不在首屏无限展开。
- 所有对象均可悬浮或点击查看定义与作用；说明采用浮窗，不占永久右栏。浮窗只保留一个小入口，目前仅“模型”的“进入模型优化”可用，跳至已有模型课程；其余对象显示禁用的“对应内容待开放”。不在导览浮窗加入证据、检查项或诊断建议。
- 悬浮查看，点击固定浮窗；移入浮窗可操作按钮，Escape、关闭按钮或点击外部收起。仅可用按钮才离开地图。支持平移/缩放/恢复全图，默认不允许拖节点、连边或编辑关系；滚轮不劫持整页阅读。
- 例如“记忆”：定义为管理可在后续交互中使用的信息的机制；作用为保存和取回任务历史、关键信息或偏好，为后续任务提供所需信息。浮窗入口标为“对应内容待开放”，不可跳转。
- 模型节点提供《模型优化》入口；未制作的章节显示真实状态，不跳转空白页面。
- 地图下的全局阅读入口进入总纲运行章节，实操入口进入案例查询；浮窗只开放已具备内容的模型课程，不把其他对象重定向为同一段通用说明。
- 对象地图表示关系；核心决策图表示判定路径，两者使用不同标题与交互规则。

### L2 逐步展开的完整讲义

- 按学习任务分节，每节有“要解决的问题、概念解释、交互图或表、证据示例、检查问题、下一步”。这是内容模板，不强制每节塞入同样数量的模块。
- 同一节保留连贯阅读，复杂细节折叠；不把每一段文字改成需要点“下一步”的关卡。
- 图文相邻。对象图支持选择查看，三种方法用Tabs切换入口，决策图逐节点判断；少量静态表用语义表格，确有大量结果/排序/检索需求时才使用Data Table。
- 文章主线默认展开；Accordion/Collapsible仅收起补充解释、长例子或技术详情。正文不能因交互被切成必须逐次点开的碎片。
- 每段主要解释后紧邻相关图表与短结论。关系图、循环流程、对照表、消息记录分别采用相应组件，不把原始Trace全部节点塞入一张大图。
- 四环节采用可播放/暂停/逐步/重置的回路组件，外层①/⑥和内部②–⑤分开；切换环节同步解释与例子。导航紧凑且名称简短，不用小字或异常大间距来凑布局。
- 小练习先让用户作答再反馈判断依据。参考答案与材料版本绑定；存在争议的案例不提供伪确定答案。
- 从实操打开知识说明时优先用侧栏；需要进入完整课程时保留实操位置和已保存状态。

### L3 阅读与实操之间的动线

- 首次学习：首页 → 前言与架构演示 → 第1章对象地图 → 方法正文 → 局部练习 → 下一节。练习可修改或继续阅读，不强制全部答对才前进。
- 带案例：调优定位实操—langfuse → 找到会话 → 选择Trace → 拆解与步骤预览 → 定位核对 → 确认起点 → 决策树；Trace ID可直接到达目标并保留所属会话，不要求先走完课程。
- 实操中遇到概念：当前任务内展开短说明；需要长文才进入课程，返回后恢复阶段、循环、环节、证据位置与未提交草稿。
- 同时保留地图选中对象/视口、课程锚点/滚动位置、三种定位方法的各自输入。切换同一任务的视图不清空判断。
- 每个任务区只有一个主要提交动作；次级操作为看原文、补信息、调用辅助等。按钮名称描述当前阶段的结果。

## 6. 实操端需求

### O1 先理解会话，再选定一次运行

- 模块名称为「调优定位实操—langfuse」。默认结果按Session组织，显示会话摘要、Trace数量与时间，先理解上下文再选主Trace。
- Session/Trace ID精确查询与关键词查询范围明确；直接给出Trace ID时定位该条并保留所属会话，不强制从全部会话重找。无Session的Trace单独保留，不伪造共同会话。项目/时间和查询覆盖可见。
- 检索采用紧凑工具栏，主区先展示会话结果；进入会话后以运行时间线和所选Trace预览衔接。唯一主操作为“拆解这条Trace”，明确作用于所选记录。历史为右上角按需抽屉，取消目录中的“我的排查记录”与常驻继续按钮。
- 结果展示匹配字段和片段、会话/Trace、时间、用户请求与最终输出摘要；显示分页和已查询范围。
- 关键词检索可能命中 Observation 输入输出；实际支持范围由部署版本和应用适配层决定。不能把仅检索 Trace 名称的结果表述为“搜索全部内容”。
- 用户选择主要 Trace，可以附带同 Session 的上下游轮次作为对照。Session、Trace、Observation 不按固定一一关系解释。
- 记录异常表现与预期。用户尚不明确预期时，可以先探索，但对应判断保持待补充。
- 会话内单选主要Trace；可直接查看该条请求和回复、关联前后轮次。关键词命中子记录时标注命中位置，并保留完整会话上下文。匹配片段与长原文按需展开，不挤成超宽表格。

### O2 看懂一次运行

- 选Trace后先以过程状态展示拆解：读取记录、识别主循环与边界、整理原文关联。正式进度由真实任务驱动，支持取消、失败恢复，换Trace后不允许旧任务覆盖新结果。
- 完成后以步骤为主的双栏：左侧默认只列Trace和步骤，约265px；右侧并排展示本步输入与输出，下面核对预期。点步骤标题只选择该步骤，不自动展开或跳到子环节。“查看内部拆解”才展开实现环节与原始记录，原始树仍可切换。核对中阅读其他步骤不自动改变当前任务，支持返回当前核对步骤。

- 网站用以下教学结构解释一次交互型运行：Trace 外层包括①请求接收与任务状态读取、Agent Loop、⑥输出处理与交付；Loop 内重复执行②上下文准备、③模型调用、④动作执行（按需）、⑤结果处理与状态更新，再进入下一次循环。

```text
Trace（当前交互型案例中，通常对应一次用户交互的运行）
├─ ① 请求接收与任务状态读取
├─ Agent Loop
│  ├─ 循环1：②上下文 → ③模型 → ④动作（按需）→ ⑤结果/状态
│  ├─ 循环2：②上下文 → ③模型 → ④动作（按需）→ ⑤结果/状态
│  └─ ……根据实际运行结束或继续
└─ ⑥ 输出处理、交付与展示
```

- **定位阶段的确认粒度到步骤为止，当前交互型案例的一步对应一次主要循环。** 通过本步输入、模型产出及动作结果与预期比较，判断符合、存在偏差或资料不足。内部环节可按需回查，不要求学员先选到具体子环节。详细模型上下文和具体机制在后续方向排查阶段展开。
- 六环节是运行职责的分类；②–⑤位于循环内部，①/⑥通常是外层边界。不能再表述成“每个步骤各有六个环节”，也不能把所有环节画成只执行一次的六步向导。
- Observation 是原始执行记录，可映射到某次循环的某个环节，也可属于①/⑥或跨多次循环的容器；一个环节可能对应多条记录。原始层级与教学层级双向联动，不要求一条 Observation 等于一个步骤。
- 系统按实际埋点给出循环边界与环节映射草稿，用户确认或修正；用于某次调用的上下文归该次调用所在循环，不漏掉调用前的准备记录。
- 不执行工具、提前失败、输出流式交付或无法识别循环时按实际记录表达。缺记录与未发生分开，无法识别的部分留待确认。①/⑥也可作为异常位置被选中。
- 并行执行、重试、跨轮次、缺少父子引用均有明确显示，不能仅用时间顺序编造因果链。
- Trace 的实际边界由应用埋点决定，不把“一个 Trace = 一轮用户对话”当作所有 Agent 的平台规则。
- 默认先核对步骤的输入与输出。输入概览展开本次任务与前序动作反馈，完整调用输入保留并可展开；输出包含本步模型产出、动作请求和实际结果。系统规则、工具定义不删除但不全部默认铺开。每一步分别保存预期和判断，切换下一步不套用上一条预期。内部拆解中的数字明确是记录条数，不冒充模型调用次数。

### O3 选择入口、逐步核对并确认定位起点

- 拆解完成后提供关键词、异常状态、顺序核对三个入口；左侧手选步骤作为范围。查看内部环节或原始记录只帮助理解，不改变步骤级定位范围，不等于确认异常。由“开始定位”进入核对。
- 核对过程中一次只呈现当前问题：预期未知则先补充；符合则看下一处；存在偏差则记录差异；资料不足则询问缺口、让用户补充或保留待核对。LLM仅按需辅助，不能补造现场事实。
- 三种入口共用“看本步输入/输出 → 对照预期 → 符合则核对下一步、偏差则记为候选、资料不足则补充”的过程，内部环节和上下游只在需要时展开。①/⑥边界记录仍保留，不因简化主线而丢失。
- 形成候选后展示“定位到：步骤X（待确认）”，保留该步骤预期与差异。用户可调整或继续核对；确认后才进入方向决策。报错或关键词命中不直接作为异常结论。
- 默认关联候选步骤本身的模型调用。若疑点是动作反馈影响后续判断，允许显式选择实际接收该反馈的后续调用；依据调用/反馈引用关系展示选择，不静默跳步，也不随意取最后一次模型调用。
- “执行状态异常”和“业务表现不符合预期”分开标识。
- 三种方法共用证据与核对区，切换只更新方法所需控件。不强制每个正常循环写长说明；不符合/证据不足时记录具体偏差或缺口。

**产品建议：在定位阶段提供“LLM 辅助定位”，默认不自动调用，人工定位仍可完整使用。** 它最适合帮助理解复杂记录和检查业务预期，使用方式为：

| 方法 | 先由程序完成 | LLM 可选辅助 | 用户最终操作 |
| --- | --- | --- | --- |
| 关键词 | 字段检索、命中定位到循环/环节 | 根据描述建议同义词，解释命中与问题的关联 | 选择搜索词或候选，核对原文 |
| 异常状态 | 列出真实错误、超时、重试及配置明确的异常条件 | 解释异常链，建议先核对哪些上游循环/环节 | 确认回查路径与关键位置 |
| 从头对比 | 顺序与关联记录展示 | 根据用户明确的预期，建议首个可见偏差、受影响位置和待补信息 | 核对并提交本人判断 |

- 一次辅助请求可以覆盖用户选定的一段循环，也可以只核对当前循环；界面明确范围，不静默扫描所有会话。
- 返回候选循环/环节、实际记录引用、偏差说明、建议回查方向、缺失信息。证据只能支持“首个可见偏差”时，不声称找到了真实根因。
- 用户可点候选跳到原文；“加入待核对”只建立待查项，不自动标为确认异常，更不直接生成已确认的优化对象。
- 涉及符合性比较时，业务预期不明确就先请用户补充；LLM 可建议如何表述，不能把猜测写成已确认要求。搜索词建议或已有错误解释可先进行。

### O4 确认定位后进入决策树，先核对关联模型输入

核对输入是优化方向决策的首个关键节点。携带已确认的位置、预期、引用及关联模型调用进入，不作为可绕过定位的并列默认主入口。资料不足可暂存或预览路线，不能生成已确认优化结论。

- 完整决策图固定在左侧主要工作区，默认同时呈现D1、H1–H4、D2、E1及7类候选对象；右侧检查当前节点，内部切换判断、原文引用与已走路径，不增加第三个常驻窄栏。
- 答案草稿不推进；显式提交后才按共享domain规则更新路径，已走连线转蓝、当前圆环短暂强调。未走分支保持清晰可读；点击未来节点只读预览，不改变当前位置。证据不足停留当前节点，上游改答归档旧版本并重新核对下游，候选结果保持待验证。

- 默认展示选定模型调用实际收到的输入输出，而非仅展示 Trace 顶层摘要。
- 输入按材料中的六类来源辅助阅读，保留原始顺序、角色、字段位置和完整原文。分类可修正，无法识别的内容保留为未分类。
- 用户分别判断齐全、精准、一致，每项可选“满足 / 不满足 / 证据不足”，附依据和引用。
- 三项状态同时可见，使用Radio Group；只展开当前依据编辑区。当前调用引用自动带入，允许三项共用引用；满足时备注可选，不满足/证据不足时填写偏差或缺口，避免重复抄写上下文。
- 角色消息与原文为默认阅读方式，JSON和差异对比按需打开；来源标签不重排原始消息，避免读者为了核对标准先学习数据格式。
- 通过标准只能说明输入在当前证据下满足要求，不能直接等同于模型有问题。还需判断输出、动作、性能是否满足任务要求。
- 按材料核心路线进入 Harness、模型、运行环境与安全监测、架构设计等分支。每个节点显示判定问题、检查依据、当前证据和所选答案。

### O5 用户可选的 LLM 辅助

- 定位阶段提供“LLM 辅助定位”；上下文和核心决策阶段提供“请 LLM 辅助这次判断”。两种用途分别记录，均由用户主动触发，一次点击对应一次辅助请求，不自动连续执行整条 SOP。
- 定位输出采用 O3 的候选结构；判断输出采用“建议判断、支持证据、反向证据、缺失信息”结构，可展开查看模型与请求时间。
- 用户可采纳、修改或忽略。采纳后仍需显式提交本人的判断；意见冲突时并排呈现。
- 请求失败或超时不阻塞人工操作；不会自动重试产生额外调用。
- 来源中的文字均作为待分析数据，不能指挥辅助模型更改 SOP、调用工具或执行生产动作。
- 辅助准备、建议和失败反馈优先放在当前任务内，关闭辅助区不丢原文位置。采纳先填入草稿，再由用户使用同一个提交动作保存，不叠加多层确认窗口。

### O6 形成排查记录

- 产出候选对象、支持/反向证据、未决问题、决策路径、下一步验证计划及相关课程。
- 保留多个候选并支持人工排序，理由以证据、收益、成本、影响和可回退性说明，不生成未经校准的“根因概率”。
- 状态为“进行中 / 待补充 / 已形成候选 / 已补充验证结果”等；不把完成向导自动表述为问题已修复。
- 推荐支持保存、重新打开和导出排查摘要。首次发布应能恢复人工判断与证据引用；多人同时编辑暂不列为首期必需。
- 结果阅读顺序为问题/预期 → 候选及主要依据 → 下一步/待补 → 验证计划；长路径、原始ID与版本集中到可展开详情。少量候选用简表，验证动作用清单。

## 7. 首期边界与交付顺序

**当前执行顺序：先完成并评审交互动线，再改造正式原型，满意后按内部部署对接实时API与LLM。** 正式应用已使用实际JSON离线导出；本轮独立交互稿同样使用真实会话关系、映射和原文节选，加载与定位过程为交互演示。LLM尚未配置，入口禁用，不返回预设辅助意见。内部API仍未联通；后续真实接入须满足O1–O6及相应验收标准。

| 阶段 | 必须完成的工作 | 验收方式 |
| --- | --- | --- |
| 产品与 SOP 设计 | PRD、材料映射、节点规则、页面状态、组件与接口能力清单 | 用一条真实案例核对每个状态所需输入输出 |
| 逐页交互设计 | 导览、对象地图、课程页、案例检索、完整工作台、结果页 | 可点击检查前进、补材料、调用辅助、回退修改；明确设计稿数据性质 |
| 首个真实闭环 | 实际部署 API → 确认 Trace → N 步拆解 → 定位 → 判断 → 候选对象 | 使用真实可授权读取的案例；重开记录可恢复；没有用预置内容替代查询 |
| 总纲内容完善 | 全部总纲章节及交互图表、练习反馈；保留模型课程入口 | 与 PDF 对照无遗漏，争议案例完成核对 |

产品首期不包含直接修改生产 Prompt、Skill、模型配置、自动发起原始任务重跑。当前“LLM 辅助”是新的诊断请求，不能伪装为原 Agent 的原样重放。

## 8. 关键验收场景

1. 输入真实 Session ID，列出实际 Trace；选中后能查到模型调用的原始输入输出，来源 ID 可回查。
2. 关键词查询显示实际覆盖字段和范围；部分记录不可读时不会显示成“全量无结果”。
3. Trace 外层①/⑥、内部 N 次循环、每次涉及的②–⑤及其 Observation 可双向定位；不预置六个步骤，不为未执行动作补造记录。
4. 三种方法任一进入同一核对循环；用户可以标记多个候选循环/环节并回查上游。边界①/⑥异常可直接标记。
5. 原始输入缺失、截断或多模态附件不可读时，无法误标为证据完整或自动通过检查。
6. 用户不调用 LLM 也能完整走完判断；调用后建议不会覆盖其原答案。
7. 改变 Trace、拆分版本或上游判断后，依赖旧证据的下游结论显示待复核，原记录可追溯。
8. 从候选模型对象打开模型课程，再回实操时保留位置与判断。
9. 真实案例的练习反馈展示证据质量和未决事项，不用固定答案判用户对错。
10. 结果页中执行错误、业务异常、用户判断、LLM 意见与最终候选对象可清楚区分。
11. 所有对象可查看定义/作用浮窗，仅模型浮窗入口可跳转；其他入口禁用，不展示证据、检查项或诊断建议。
12. 定位可完全不用 LLM；主动辅助后能跳到候选循环的真实记录，建议不自动确认异常或推进核心决策。
13. LLM 定位所用范围、预期、映射版本和证据版本可回查；输入不足、结果越界或引用不存在时不展示为可信的候选依据。
14. 所有屏幕文案均为读者实际使用的内容；受众、尺寸、组件名和设计提醒不渗入正文布局。
15. 导览地图默认连续协作动画，可暂停；悬浮/点击查看对象不被动画覆盖，滚动页面不被图劫持；列表不替代主图。
16. 学习与实操相互返回、定位方法和证据视图切换后，位置、范围、输入和未提交判断可恢复。
17. 三标准共用实际输入与引用，不默认作答；LLM采纳不会产生额外的隐式提交。
18. 错误、保存失败、证据不足、未确认映射和非模型位置都有下一步；页面不能靠关闭按钮、重置或强填无关字段才能继续。
