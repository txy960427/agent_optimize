## 原问题

- 1440×900下首页2的Hero高782px；1268×550下标题与操作随高演示垂直居中，入口移到首屏外。
- 演示内部为窄竖向目录加窄正文。所有场景放在同一网格维持稳定高度，最长场景叠加过大的最小高度与多组底部说明，撑高整块。
- 前言正文最大688px，而表格区域最大1100px，分别居中。1440宽下正文左边为496px、表格为290px，相差206px。
- 目录、首页、阅读样式在多个历史文件重复覆盖。缺乏统一宽度与强调级别，比“颜色数量少”更直接地影响观感。

## 首屏规则

桌面首页保留相同的左介绍、右主视觉结构。当前首页1为可操作的教学预览，首页2为书册插图，两者共用首屏预算，不强行具有完全相同的高度。取消首页跨两栏的色块；演示为白色窗口、浅工具栏与轻阴影，当前阶段用细线标记，主按钮保持唯一醒目的实色操作。

- 常规桌面视窗：Hero约占扣除顶栏后可用高度的一半至三分之二；标题、两个入口、完整主视觉优先出现，四项目标与目录紧随其后。
- 矮视窗：采用较紧凑的组件间距与书册尺寸，完整保留案例与按钮。1268×550为本次专门验收的矮视窗，也用于覆盖浏览器放大后可能出现的可用CSS空间，不推断用户实际缩放设置。
- 内容画布≤848px：左右分栏改为上下排列；介绍和入口在先。手机端不通过缩小整幅演示或截断内容来硬塞一屏，正常向下阅读。
- 低于本轮最矮验收高度的窗口允许页面滚动；首屏可见入口与完整阅读优先于固定百分比。

首页1将五阶段导航横置，为正文腾出完整宽度。场景仍逐幕播放，支持暂停、重播、手选和下一阶段；减少动态效果时默认停播。保持所有幕共用自然高度，不在切换时跳动。去除整幕透明淡入，细节仅轻移3px，切换时文字持续可见。设备号对话继续明确标为情境示例，不把真实根因自动写死。

| CSS视窗 | 首页1 Hero高 | 首页2 Hero高 | 两版入口与桌面主视觉 |
| --- | ---: | ---: | --- |
| 1920×1080 | 约520px | 500px | 均完整位于首屏 |
| 1440×900 | 约520px | 495px | 均完整位于首屏 |
| 1268×550 | 约415px | 320px | 均完整位于首屏 |

高度以测试结果为准；字号与系统字体差异可能带来少量自然变化，验收条件以完整可见、无裁切为准。

## 侧栏、对齐与信息宽度

首页1、首页2及所有实操路由（`/cases`、`/work/*`、`/findings/*`）默认收起目录，不占常驻栏宽度；左侧28×52px半圆箭头可打开同一份全书目录。打开为覆盖层，不改变主画布尺寸。支持关闭按钮、遮罩与Esc，焦点回到原展开柄。材料阅读页使用下表规则。

| 材料阅读页CSS视窗 | 左侧导航 | 说明 |
| --- | --- | --- |
| ≥1700px | 240px | 1920屏约12.5%，不随大屏继续膨胀 |
| 1400–1699px | 232px | 1440屏约16.1% |
| 1100–1399px | 224px | 1280屏约17.5% |
| ≤1099px | 常驻占用0；目录抽屉最大296px | 保留至少48px遮罩区域，可关闭、Esc退出、焦点回到触发器 |

比例是材料页固定宽度在相应屏幕下的结果，不是布局公式。目录独立滚动，阅读区不受其展开长度影响；由窄屏放大到桌面时自动关闭抽屉，解除正文锁定。进入材料恢复阅读目录；返回首页或实操自动收起，不将此前的展开状态强加到新任务。

阅读页采用“居中的版心＋左对齐的文字”。段落、各级标题、表格外框、图注共享左边线。普通正文与表格最大640px；复杂三列表和角色表在手机上仅自身横向滚动，提供键盘焦点。两列说明表允许自然换行，不人为撑大。

二维对象图、决策图需要观察关系，使用最大1312px的宽舞台，标题与图的左边线一致；工作台以实际可用宽度容纳表格、证据和任务栏。它们不套用长文版心。右侧节内目录只在内容画布达到1024px后出现，避免挤压正文。

## 颜色角色

保留蓝色基调，建立六种有用途的色彩家族，加一套中性色。界面同时最多以一个操作色作为视觉主角；业务状态仍有文字或图形说明。

| 家族 | 实色 / 深色文字 | 浅底 | 用途 |
| --- | --- | --- | --- |
| 深海军蓝 | `#182B50` | — | 标题与书册，教学预览采用白色窗口 |
| 靛蓝 | `#3E52DC` / `#2D3EB8` | `#EEF1FC`、选中底`#E0E6FF` | 主按钮、当前位置、当前决策节点、进度 |
| 青绿 | `#0A8072` / `#086B60` | `#E5F4EF` | 通过、已走过的步骤、验证与资产闭环 |
| 琥珀 | `#EFB240` / `#754600` | `#FFF4D9` | 问题现场、证据待补、待核对；亮色作强调，文字使用深色 |
| 紫色 | `#7956CF` / `#6942B6` | `#F0EAFB` | 模型对象与类别语义 |
| 红色 | `#BC3C48` | `#FCEBED` | 明确错误，避免把待判断染成失败 |
| 中性 | 正文`#303B4E`、次要文字`#56647B` | 页面`#F8F9FC`、阅读面白色 | 长文、辅助说明、框架层次 |

表格使用统一浅靛蓝表头、深色表头文字、轻条纹与明确选中底。主操作、当前决策和异常场景已使用实色或有对比的强调，正文仍维持安静的阅读面。

## 实现与验收

- `web/src/styles/layout.css`：共享壳层、导航断点、正文版心、表格与语义令牌。
- `home-focus.css`：两版首页与章节导览；`home-sop.css`：五阶段演示；移除旧的多轮首页样式覆盖，取消`guide-polish.css`对首页的二次配置。
- 导航抽屉支持焦点限制、Esc、关闭后焦点恢复；表格横向滚动支持键盘；播放行为保留已有减少动态效果与离屏暂停规则。
- `npm run test:layout`：11种视窗×7类页面，包含1268×550、320×740；检查桌面首屏完整、各尺寸入口可见、无整页横向溢出、表格与正文对齐、抽屉开关/焦点/跨断点恢复、五组关键文字对比度≥4.5。另检查两版首页及实操与阅读页往返时的目录模式、打开目录不挤动画布，以及实际导出案例在工作台与结果页开关目录后记录保持不变。
- 首页SOP和阅读锚点另外回归；实操本轮检查实际导出案例的导航与记录保留。新实操业务完整流程由对应工作台的回归脚本核验，旧版`real-workspace-check.mjs`的控件约定需要随工作台重构更新。

本次局部预览与完整测量输出在`web/test-results/layout-after/`，修改前记录在`layout-before/`。所有浏览器验证均使用独立无头浏览器，不读取用户已有窗口或桌面屏幕。
