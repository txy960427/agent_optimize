# 调优定位实操—langfuse：正式站点接入

2026-11-26。将 flow-v3 动线接入 `web/src`，替换正式 `/cases`、`/work/:id` 页面。此说明覆盖早期 v0.9 文档中的实操布局、入口和阶段切换；原始数据、SOP 分支与引用契约沿用。

## 页面和动线

```text
会话 → 会话中的 Trace → 读取并拆解
  → 左侧步骤 / 右侧输入输出
  → 关键词、ERROR 或顺序核对
  → 本步预期 → 符合 / 存在偏差 / 资料不足
  → 确认候选步骤与关联模型调用
  → 完整决策图 / 当前节点检查
  → 原文引用、提交人工判断、形成候选
  → 记录与验证
```

- 全书目录默认收起，左侧半圆箭头覆盖展开；页面内步骤树与全书目录独立。历史收进右上角抽屉。
- 默认按真实 Session 聚合；34 个 Session，另有 7 条无 Session 的独立 Trace。关键词、案例或条件命中后保留完整会话上下文，命中数与会话总数分开显示。会话内按时间正序选 Trace。
- 数据按需读取；加载提示反映真实读取，不伪造进度。失败可重试，不回退到设计数据。
- 左目录默认只显示步骤。点击步骤不自动展开或跳环节；②—⑤内部拆解显式展开，①请求准备与⑥交付在循环之外。辅助模型不混入主步骤，完整原始树保留。
- 核对对象和阅读位置分开：核对步骤 1 时可以阅读步骤 2，各步骤预期、判断、偏差和资料缺口独立保存。资料不足只能补充或暂存，不直接确认候选。
- 定位确认到步骤为止。下一阶段默认本步模型；只允许明确选择通过实际 `tool_call_id` 关联、收到该动作反馈的后续调用。不静默选择最后一个模型。

## 决策与保存

7 个判断点、7 个候选对象常驻完整图，路由直接使用 `domain/data.ts` 的既有规则。D1 逐项核对齐全、精准、一致。选择为草稿，提交后才改变路径和高亮；未来节点只读预览，不可越级提交。新节点保留前面已提交的答案；改判此前节点则归档旧路径、清除后续判断与旧验证结果。资料不足停留待补，不适用仅在规则允许处出现。

「原文与引用」复用正式 RecordReader，保留消息、角色、顺序、工具定义、调用参数、结果和原始字段路径。工具反馈概览提取正文便于阅读，完整结构仍可回查。候选方向尚待验证，验证计划和实际结果分开保存。

沿用浏览器存储键 `agent-tuning-real-export-v1`，不清空旧记录。新增可选 `practice` 状态，缺失时根据旧 stage/loop/expected 等字段恢复默认值。原始轨迹按 ID 重读，不存整份数据。映射变动或内容指纹变化会使旧判断待复核。

## 视觉与组件

指南保持原有阅读风格。实操使用深蓝顶栏 `#172B49`、白色工作区、辅助灰 `#F5F6F8`、正文 `#253043`、次要文字 `#667284`、边框 `#DCE1E8`、操作蓝 `#2E65D3`，圆角 4–6px。普通文本 12–13px，标题 20–22px。React Flow 展示决策图，Radix Dialog 展示历史/说明抽屉，正式记录查看器和映射编辑器复用。

桌面步骤页两列，空间足够时输入输出并排；窄屏目录和内容上下排列。850px 以下决策图与检查区上下排列，保留缩放、拖动和节点列表。减少动态偏好下关闭非必要动画。

## 接口与实施边界

| 新增 GET 路径 | 能力 |
| --- | --- |
| `/api/local-data/sessions` | Session 聚合、查询与分页；`group=sessions/unassigned`，兼容原查询条件 |
| `/api/local-data/sessions/:id` | 当前导出内该 Session 的全部 Trace 摘要，时间正序 |

Trace 详情仍用 `/api/local-data/traces/:id`。只读接口运行于现有 Vite 开发/预览服务；设计稿的 `flow-data.json` 不进入正式前端。

本次使用本地真实离线导出；未接实时 Langfuse API、LLM、服务端持久化和多人协作。多个步骤联合送入决策、基础信息常驻方式的进一步优化留待后续设计；当前确认一个定位步骤、选择一个关联模型调用，可引用其他实际记录补充。
